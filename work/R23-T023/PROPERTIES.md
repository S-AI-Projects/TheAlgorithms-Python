# Mathematical Properties and Invariants: `hex_to_rgb`

This document outlines the formal mathematical properties, invariants, and empirical findings obtained from property-based testing of `conversions/hex_to_rgb.py` using **Hypothesis**.

---

## 1. Mathematical Domain & Foundations

### Color Spaces
1. **RGB Color Space**:
   $$\mathcal{C}_{\text{RGB}} = \left\{ (r, g, b) \in \mathbb{Z}^3 \;\middle|\; 0 \le r, g, b \le 255 \right\}$$
   Total cardinality: $|\mathcal{C}_{\text{RGB}}| = 256^3 = 16,777,216$ distinct colors.

2. **6-Digit Hexadecimal Representation**:
   $$\Sigma_{\text{hex}} = \{0, 1, \dots, 9, \text{a}, \dots, \text{f}, \text{A}, \dots, \text{F}\}$$
   A 6-digit hex color is a string $s \in \Sigma_{\text{hex}}^6$ (optionally prefixed by `'#'`).

3. **3-Digit Shorthand Representation**:
   A 3-digit hex color is a string $s \in \Sigma_{\text{hex}}^3$ (optionally prefixed by `'#'`).
   It expands to 6 digits by duplicating each nibble:
   $$d \mapsto 16 \cdot d + d = 17 \cdot d \quad \text{for } d \in \{0, \dots, 15\}$$

## 2. Tested Properties and Invariants

### Property 1: Full 6-Digit Round-Trip Bijection
- **Definition**: For any valid RGB tuple $(r, g, b) \in [0, 255]^3$, let $\text{rgb\_to\_hex}(r, g, b)$ produce a standard 6-digit hex string. Applying $\text{hex\_to\_rgb}$ must return the formatted string `"rgb(r, g, b)"` matching $(r, g, b)$ identically.
- **Formulation**:
  $$\forall (r, g, b) \in [0, 255]^3, \quad \text{hex\_to\_rgb}(\text{rgb\_to\_hex}(r, g, b)) = \text{"rgb}(r, g, b)"$$
- **Hypothesis Strategy**: Over 2,500 pseudorandom samples drawn independently across $r, g, b \in [0, 255]$, verified across all permutations of leading `'#'` presence and uppercase/lowercase formatting.
- **Result**: PASSED with zero failures.

### Property 2: 3-Digit Shorthand Expansion Round-Trip
- **Definition**: For any 3-digit hex string $\#d_1 d_2 d_3$, where each digit $d_k \in \{0, \dots, 15\}$, the expansion maps $d_k \mapsto 17 \cdot d_k$.
- **Formulation**:
  $$\text{hex\_to\_rgb}(\#d_1 d_2 d_3) = \text{"rgb}(17 d_1, 17 d_2, 17 d_3)"$$
- **Hypothesis Strategy**: 1,000 random samples across all 4-bit nibbles $d_1, d_2, d_3 \in [0, 15]$ testing both uppercase and lowercase formatting.
- **Result**: PASSED with zero failures.

### Property 3: Case and Prefix Invariance
- **Definition**: The parsing operation is invariant under casing (ASCII uppercase vs. lowercase) and the presence of a single leading `'#'` prefix:
  $$f(\text{"#"}+s_{\text{upper}}) = f(\text{"#"}+s_{\text{lower}}) = f(s_{\text{upper}}) = f(s_{\text{lower}})$$
- **Hypothesis Strategy**: 1,000 independent samples across $[0, 255]^3$.
- **Result**: PASSED with zero failures.

### Property 4: Rejection of Invalid Lengths
- **Definition**: Any input string $s$ whose length after stripping leading `'#'` satisfies $|s| \notin \{3, 6\}$ must raise `ValueError`.
- **Formulation**:
  $$|s \setminus \text{leading } \text{'\#'}| \notin \{3, 6\} \implies \text{hex\_to\_rgb}(s) \text{ raises } \text{ValueError}$$
- **Hypothesis Strategy**: 1,000 strings of lengths $0 \dots 20$ excluding 3 and 6.
- **Result**: PASSED with zero failures.

### Property 5: Rejection of Non-Hex Characters
- **Definition**: Any string containing characters outside $\Sigma_{\text{hex}}$ (e.g., characters `g-z`, `G-Z`, symbols like `@`, `!`, `?`, `$`) must raise `ValueError`.
- **Hypothesis Strategy**: 1,000 strings of lengths 3 and 6 injected with non-hex characters.
- **Result**: PASSED with zero failures.

### Property 6: Arbitrary String Rejection
- **Definition**: For arbitrary strings generated by `st.text()`, any string that does not adhere to `#?[0-9a-fA-F]{3}` or `#?[0-9a-fA-F]{6}` must raise `ValueError`.
- **Hypothesis Strategy**: 1,500 arbitrary strings.
- **Result**: PASSED with zero failures.

## 3. Boundary Inputs Exposed & Added Doctests

From the property tests, four distinct boundary behaviors were identified:
1. **3-digit shorthand** (lowercase and mixed characters):
   - Example: `hex_to_rgb("#abc") -> 'rgb(170, 187, 204)'`
2. **Lowercase 6-digit hex**:
   - Example: `hex_to_rgb("#ff2000") -> 'rgb(255, 32, 0)'`
3. **Missing `'#'` prefix**:
   - Example: `hex_to_rgb("FF0000") -> 'rgb(255, 0, 0)'`
   - Example: `hex_to_rgb("123") -> 'rgb(17, 34, 51)'`
4. **Invalid lengths**:
   - Example: `hex_to_rgb("#12345") -> raises ValueError`
   - Example: `hex_to_rgb("") -> raises ValueError`

All 6 boundary cases have been integrated into the doctests of `conversions/hex_to_rgb.py` alongside the 8 original doctests (total 14 doctests, all passing).

## 4. Hypothesis Discovery: Implementation Limitation

### Discovered Behavior
During exploratory property testing, Hypothesis discovered minimal inputs such as:
- Minimal space input: `"#00000 "`
- Minimal sign input: `"#0000+0"`

### Technical Analysis
In `conversions/hex_to_rgb.py`, length validation is performed before parsing:
```python
if not (len(hex_color) == 6 or len(hex_color) == 3):
    raise ValueError("Invalid hex color code")
```
However, individual characters are parsed directly using Python's built-in `int(slice, 16)`:
```python
red = int(hex_color[0:2], 16)
green = int(hex_color[2:4], 16)
blue = int(hex_color[4:6], 16)
```
Python's built-in `int(str, base)` automatically strips leading/trailing whitespace and accepts unary `+` or `-` signs. Consequently:
- `int("0 ", 16) == 0`
- `int("+0", 16) == 0`

Because the function does not validate against a strict character set (e.g., regex `^[0-9a-fA-F]+$` or `c in string.hexdigits`), strings with whitespace or unary signs within 2-character slices do not raise `ValueError` and evaluate to `rgb(0, 0, 0)`.

As mandated by the repository guidelines ("Please avoid changing both code and tests in a single pull request") and the task instructions ("whichever the function supports, with documented behaviour"), the existing code logic and raise statement are preserved, and this parsing quirk is formally documented here and verified by `test_hypothesis_discovered_limitation_minimal_example()` in the test suite.
