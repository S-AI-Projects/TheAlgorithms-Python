# Mathematical Properties and Verification for `is_int_palindrome`

This document details the property-based testing and verification conducted on `maths/is_int_palindrome.py` for task `R23-T001`.

## Tested Properties

### 1. Non-Negative Integer Equivalence Property
- **Formal Statement**: $\forall n \in \mathbb{Z}_{\ge 0},\ \text{is\_int\_palindrome}(n) \iff (\text{str}(n) == \text{str}(n)[::-1])$
- **Description**: For all non-negative integers, whether an integer is palindromic must match the canonical string representation reading identically forwards and backwards.
- **Verification**: Tested against $\ge 1,000$ random non-negative integer inputs generated by Hypothesis (`st.integers(min_value=0)`).

### 2. Negative Integer Property
- **Formal Statement**: $\forall n \in \mathbb{Z}_{< 0},\ \text{is\_int\_palindrome}(n) = \text{False}$
- **Description**: Negative numbers begin with a negative sign (`-`), e.g., `-121`. Because the reverse would have the minus sign at the end (`121-`), negative numbers cannot be palindromic integers.
- **Verification**: Tested against $\ge 1,000$ negative integer inputs generated by Hypothesis (`st.integers(max_value=-1)`).

### 3. Constructed Palindrome Property (Symmetry Invariant)
- **Formal Statement**: $\forall \text{prefix} \in \mathbb{Z}_{> 0}, d \in \{0, \dots, 9\}$:
  - $\text{is\_int\_palindrome}(\text{int}(\text{prefix} + \text{prefix}^{\mathcal{R}})) = \text{True}$
  - $\text{is\_int\_palindrome}(\text{int}(\text{prefix} + d + \text{prefix}^{\mathcal{R}})) = \text{True}$
- **Description**: Any positive integer constructed by mirroring its digits (both even and odd lengths, including arbitrary-precision integers exceeding 19+ digits) must be recognized as a palindrome.
- **Verification**: Tested across $\ge 1,000$ generated palindromic structures.

### 4. Type Safety and Input Validation
- **Formal Statement**: $\forall x \notin \mathbb{Z} \lor x \in \text{bool},\ \text{is\_int\_palindrome}(x) \implies \text{raises } \text{TypeError}$
- **Description**: Since boolean values are subclasses of `int` in Python, they evaluate to 0 or 1 unless explicitly checked. To prevent unintended truthy/falsy behavior or invalid types (floats, strings, None, collections), a `TypeError` must be raised.
- **Verification**: Tested with $\ge 1,000$ varied non-integer inputs generated via `st.one_of`.

## Boundary Cases Explored

1. **Zero (`0`)**: Smallest non-negative integer, single digit, trivially palindromic (`True`).
2. **Single-digit numbers (`1` to `9`)**: Always read identically backwards and forwards (`True`).
3. **Trailing zeros (`10`, `120`, `1210`)**: Reversing leaves leading zeros which changes magnitude, making them non-palindromic (`False`).
4. **Large arbitrary-precision integers (19+ digits)**: Tested large numbers like `1234567890987654321` (19 digits) to ensure the numerical extraction loop handles arbitrary size without overflow or precision loss.
5. **Non-integer types**: Strings (e.g., `'121'`), floats (e.g., `12.21`), and booleans (e.g., `True`) raise `TypeError`.
